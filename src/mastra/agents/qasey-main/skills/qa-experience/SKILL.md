# QA Experience

System prompt 已识别的 intent 决定执行 `experience_read` 或 `experience_write` 模式。读取和写入模式不得静默互换；一个请求同时包含两者时先读后写。

## experience_read：读取经验

- 从最相关目录开始，默认选择最相关的一至三篇，完整读取选中条目后再判断，不遍历整个经验库。
- 把经验视为历史风险线索，核对适用条件、来源和当前需求或代码；过期或无法验证时明确标记。
- 提炼可复用条件、风险、检查点和证据，不复制整篇经验，也不修改 QA Experience。

给出适用结论、可复用检查点、当前差异、来源和未知项；没有足够相关结果时直接说明。

## experience_write：写入经验

1. 确认内容是可复用的风险、条件、根因或检查方式，而不是一次性记录、猜测、隐私或密钥。
2. 定位合适目录并读取已有条目，避免重复；编辑时基于完整旧正文形成最终覆盖内容。
3. 候选内容区分事实和未知，包含适用场景、风险、触发边界、可执行检查点及真实来源。
4. 只允许在 Slack 发起审批；审批前只能展示候选内容，不得声称已写入。
5. 审批通过后执行 create/edit，并用真实标识回读标题和关键正文；拒绝、超时或回读失败都不算完成。

最终说明写入或未写入状态、目标位置、审批结果、回读结果和来源，不暴露审批内部实现。
